# Active operations and completion results

The fixed player dock shows Operations while any raid involving the settlement is in flight. This includes incoming and outgoing raids. It shows the earliest resolution countdown, updated locally every second from the existing server snapshot. Paused season/settlement clocks do not count down. Zero displays Resolving until the server commits an outcome; the client never awards loot or simulates combat. Click to open Military combat/raid details. The existing expedition shortcut remains.

Results is a separate fixed button above the dock. It shows up to 20 recent own-settlement raid/expedition results and raises a small dismissible notice for unseen entries. The server filters by settlement and season; no other player's report feed is exposed. Summaries show delivered loot, storage overflow, raid Credits and participating citizen injuries/deaths. Expedition summaries distinguish gathered materials from delivery including unused provisions. Full existing reports retain capture, equipment, building damage and other details.

Results are backed by persisted battle/expedition records, including older completed missions. New raid resolutions create a persistent raid_result notification for both attacker and defender; new expedition returns create an expedition_return notification for their owner, in the same transaction as resolution/return. Existing idempotent status guards prevent duplicate notices. Saved notifications remain under Diplomacy; the Results button's seen badge is remembered separately in this browser per settlement. Opening Results does not mark all unrelated messages read. No save reset or schema migration is needed.

No extra network polling: the existing resource refresh carries operation results and the military snapshot. Visual countdowns are estimates between server refreshes, and the authoritative server controls every outcome. Templates and Python services changed: restart player server and admin tools with the same save, then Ctrl+F5. Bots need no restart for decision-policy purposes.

Three new Python summary/isolation cases, two JavaScript countdown cases, and notification assertions in existing combat/expedition idempotence cases were added. Full/optional UI discovery finds new files automatically. Python/JavaScript syntax checked only; tests not run. Authenticated visual verification remains pending.
